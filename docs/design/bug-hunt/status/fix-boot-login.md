# fix-boot-login: status (Wave 3, 2026-09-30)

Scope: the 18 bugs that `BUGS.md` §2 gives to fix-boot-login. The 2026-09-27 instance of this role
had already written most of the fixes and their tests. This pass reviewed that code and ran every
test. It checked each bug in the browser on the Docker build at http://localhost:4718, which sends
the real Caddy CSP. It then finished the gaps it found (listed under "Changed in this pass").

check logs. The scripts are in the session scratchpad (`fbl/*.mjs`), not in the repo. All
browser runs used chromium (channel chrome) with a CSP `securitypolicyviolation` listener.
Unless a row says otherwise, the runs were at 1440×900 and had **0 violations**.

## Changed in this pass (2026-09-30)

- `ui/src/boot/ui-067-verbose-chip.test.ts` (new): the missing UI-067 regression tests.
- `ui/src/boot/panic.ts`: the D action is now called "Diagnostics" (spec §3.6), and the header
  comment is updated. `ui/src/boot/boot-polish.test.ts`: the expected label is updated.
- `ui/src/boot/boot.css`: the panic footer is a 3-column grid, the panic action gap is tighter,
  the unsupported card is 600 px wide, and a stale compactor comment is removed.
- `web/src/boot/recovery-console.ts`: a shorter "no answer" line.
- `web/src/boot/driver.ts`: the Service Worker URL now goes through the boot Trusted Types
  policy (`swUrl: scriptUrl('/sw.js')`). On 4718, the signed-in boot had shown one
  `require-trusted-types-for` report (sample `ServiceWorkerContainer register|/sw.js`, report-only).
  After the rebuild there are 0. The `scriptUrl` factory is now created before
  `createUpdateController` and is still created only once.
- QA container `web` was rebuilt through the wrapper (`qa-compose.sh up -d --wait --build web`) to
  check these changes under the real CSP.
