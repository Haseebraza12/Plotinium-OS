## UI-006 design (for reviewers)

- **Engines.** `installIo` builds the default `EngineFactory` (`kernel/src/core/net/factory.ts`)
  when the host binds a socket, `fetch` and an origin. kernel/src/core touches no platform global:
  the worker passes vfs `browserSocket` and `navigator.locks`. A `nosync` boot flag keeps the
  device standalone (test builds: `?bootflags=nosync`). The VFS mount stays `standalone` (a local
  miss is a real miss), so enabling sync changes no read path.
- **Homes (C5).** The server mints `/home/<user>`. Online, a new local home takes the server's id
  (`ServerApi.homeIno`, a snapshot of /home, bounded by 1 s at sign-in). An existing **empty** home
  is moved to that id in one transaction. The `sync` service links the engine only when the local
  home **is** the server's. Otherwise it stays DEGRADED with the reason ("home folder made offline
  on this device (not linked to the server)"), so it never sends ops the server would reject and
  revert. Devices whose homes were made by earlier builds (the user's :4717 browser) therefore stay
  unlinked until that home is empty or the browser data is reset. Migrating a non-empty home is
  left for the RFC track.
- **OS session id.** `hello` reads the kernel's OS session id live (the `session` service replaces
  it after `sync` starts). The server accepted no op of a session other than the announced one:
  the first probe got `bye policy` on the first `op.submit`.
- **Offline sessions (server).** An OS session that ran offline never sent `hello`, so its
  replayed ops were refused with close 1008 on every reconnect. Step 1 now lets the uid's device
  claim an **unknown** session id (`INSERT … ON CONFLICT DO NOTHING`). Another uid's or another
  device's id is still refused.
- **Content.** Rows synced from another device carry only the blob hash. The kernel fetched none,
  so the Terminal's shell crashed with EAGAIN on a second device. `ContentCache` now downloads
  `GET /api/blobs/{sha}` on first read, checks the SHA-256 and stores the chunks.
- **Leases.** `lock.acquire` always arbitrates locally first (UI-002, the local EBUSY rules), then
  takes the server lease when lockd's server layer is up. A server denial releases the local lease
  and returns EBUSY with the holder.
- **Frames.** Server frames are decoded with the protocol schema. A frame that fails it but has the
  envelope is still delivered and reported to klog (at most 5 per engine), so a small
  server/client drift degrades to a warning instead of a stalled connection.
