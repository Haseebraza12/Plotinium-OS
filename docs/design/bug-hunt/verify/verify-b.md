# verify-b: independent verification of fix-files-editor and fix-terminal (Wave 3, 2026-09-30)

Verifier: verify-b. Scope: the 55 bugs owned by fix-files-editor (33) and fix-terminal (22) in
`docs/design/bug-hunt/BUGS.md`, regressions in those areas, the new fonts, and a full Terminal
session. Each bug was judged against the **Expected** of BUGS.md and the specs, not against the
fixer's status file.

## How it was checked

- **Where.** The QA copy at http://localhost:4718 (Docker build, real Caddy CSP), signed in with
  the `state-verify-b.json` session (alice). Chrome (Playwright channel `chrome`), 1440×900, device
  scale factor 1. Light and dark, plus a dark run with `prefers-reduced-motion: reduce`.
- **Builds.** First on build `6df55c0` (the gate's final build). After my fixes I rebuilt only the
  `web` image through `qa-compose.sh`, which gave build `a4f4c7c`. Every fix of mine was re-verified
  on `a4f4c7c`.
- **Every page** had a `securitypolicyviolation` listener, console-error and page-error capture.
  Result on every run: **0 CSP violations, 0 console errors**.
- **Screenshots** are in `docs/design/wave3/verify-b/`, and I read them. The Playwright scripts are
  in the scratchpad `vb/` folder and are not committed. Each fresh browser context starts with an
  empty local file system, so each Files run first creates `~/Projects` through the Terminal.
- **The e2e spec.** `tests/e2e/polish-terminal.spec.ts` (UI-131) ran on :4718 with my session: 2/2 passed.

Verdicts: **VERIFIED-FIXED**, **STILL-BROKEN** (the expected behaviour is not met, even if part
of it is), **NOT-REPRODUCIBLE**. "Fixed by verify-b" means I found it still broken, fixed it,
and re-verified it on `a4f4c7c`.

## Terminal session, end to end (4718, dark and light)

All of these ran in one Terminal with **0 CSP violations and 0 console errors**
(`term-dark-b1.png` … `term-dark-b10.png`, `term-light-*.png`):

- **Files and navigation.** `ls`, `ls -la /` (modes readable at 1x), `pwd` → `/home/alice`,
  `cd /tmp`, `mkdir x && touch x/a.md && ls x` → `a.md`.
- **Pipes and redirection.** `echo hi | cat` → `hi`. `>` then `>>`, then `cat` → `one`, `two`.
  `grep two r.txt`. `find /tmp -name "*.md"`. `tree /tmp`, with box drawing.
- **File metadata and space.** `stat` (uid/gid names, local time), `chmod 600` → `-rw-------`,
  `du -sh ~`, `df -h`, `quota`.
- **Processes.** `ps`. `top`: live, with the local clock; `q` quits. `sleep 100 &` then `kill %1`
  → Terminated. `kill 999999` → No such process.
- **Job control.** `sleep 60 &`, `jobs`, `fg`, then Ctrl-C → `^C`. `sleep 50`, then Ctrl-Z →
  Stopped. `bg` → Running. `kill %1`.
- **Memory.** `free`, `vmstat`, `pmap $$`: all print. `vmstat` and `pmap` wrap at 84 columns (see
  "Other observations").
- **System.** `uname -a` (build 6df55c0), `whoami` → alice, `id` → `uid=1100(alice) gid=100(users)
groups=100(users),200(team)`, `uptime`, `bootlog`, `history`, `help`, `man ls`.
- **Line editing.** Tab completion of commands, paths and flags. Ctrl-C clears a typed line.
  ↑↑ Enter re-runs an earlier command. New tab (Alt+Shift+N), previous and next tab, close tab: focus
  stays in the terminal.
- **AI.** `ai "list my files"` → the truthful "agent unavailable…" (UI-055). `ai status` → running
  (inconsistent, see UI-055). `semsearch plan` → results (quality issue, see UI-124). `predict` →
  "MFU fallback (1 of 50 launches)", with 3 ranked apps.

**Failed parts of the session:** `bootlog | tail -n 6` and `history | tail -n 5` → `sh: tail:
command not found`. `tail` is not in the spec. But the spec's own extra-commands table
(shell-and-terminal.md, "`head`, `wc` … used in pipelines and the flood test") lists commands that
are missing too. `head`, `wc`, `env`, `yes`, `dmesg` and `framemeter` all give "command not found".
They were never implemented; this is not a regression (handoff).

## Regressions found and fixed

1. **Files: Alt+← and Alt+→ were dead (UI-015 residual).** The desktop's navigation guard
   (window-manager.md §3.9) prevents their default in the capture phase, and Files skipped every
   prevented key. The earlier DOM test mounted Files without the desktop, so it passed. Fixed in
   `apps/files/view.tsx` and `ui/src/apps/files/FilesToolbar.tsx`. The new tests install the same
   capture-phase guard.
2. **Files: focus fell to `<body>` after Esc on the background menu or one of its items (UI-108
   residual).** This came from the race between `refocusSoon` and the menu's 100 ms exit fade. Fixed
   in `apps/files/view.tsx`. The new test waits past the fade.
3. **Editor: an Untitled document read "saved v0 · ✓ synced" (UI-117 follow-on).** It now reads "not
   saved", with no sync part. Fixed in `ui/src/apps/editor/EditorStatusBar.tsx` and
   `apps/editor/view.tsx`, with tests in both packages.

Each new test was mutation-checked: I reverted the fix, the test failed, and I restored it.

## Regression sweep with no finding

- **CSP.** 0 violations (enforced and report-only) in every run: Files, the Editor, the Terminal
  (typing, colours, Select All, `top`, the pager), Task Manager, sheets, menus, drag and drop, and
  reload.
- **Both themes.** Files, the Editor and the Terminal were checked in light and dark, including
  the layouts at 960, 720 and 640 px.
- **Reduced motion.** The Editor run in dark mode with `reduce` behaved the same. Statically, every
  `animation`, `transition` and `@keyframes` in `ui/src/apps/{files,editor,terminal}` animates only
  `transform` and `opacity`, and each has a `prefers-reduced-motion: reduce` guard.
- **Keyboard.**
  - Files: a Tab walk has no `<body>` stop. Arrow keys, Enter, Alt+↑, F2 rename, Ctrl+A and Esc
    work. Focus returns to the list after sheets and menus.
  - The Editor gets focus in its text on launch.
  - The Terminal keeps focus through tab and menu commands.
- **Session restore.** After a reload, windows come back (Terminal and Editor). Their contents do
  not (UI-112, UI-127).
- **Look and feel.** The screenshots match the macOS-style glass design in both themes.
  - The Terminal's 2 px accent inset ring on focus (`.host:focus-within`) is unchanged since the
    baseline, so it is not a regression. It is still worth a design review, since macOS Terminal
    has no content focus ring and the xterm cursor already shows focus.
