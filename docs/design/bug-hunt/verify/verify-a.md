# verify-a: independent verification of boot-login, desktop-shell and windows (Wave 3, 2026-09-30)

Scope: the 66 bugs in `docs/design/bug-hunt/BUGS.md` owned by fix-boot-login (18), fix-desktop-shell
(33) and fix-windows (15), plus a regression pass over those areas and an audit of the new logo.

## How this was checked

- Each bug was judged against its **Expected** / **Done when** text in BUGS.md and the specs, not
  against the fixer's status file. Each repro was re-run by my own Playwright scripts (scratchpad
  `va/`, not committed), with Chrome (channel `chrome`) at 1440×900. I also used 1280×800, 1024×700
  and 760×560 where layout matters, both themes, and `prefers-reduced-motion`. Every page had a
  `securitypolicyviolation` listener and console, page-error and failed-request capture.
- Target: the QA copy on http://localhost:4718 (Docker build, Caddy CSP), session `state-verify-a.json`
  (examiner1). The QA copy was rebuilt four times during this pass: 6df55c0 (gate), 0872260 (another
  verifier), then a4d7a39 and 5c9f63a (mine, web only, through `qa-compose.sh`). The final regression
  sweep ran on **5c9f63a**, which contains both of my fixes. Every run on every build had
  **0 CSP violations** (enforced and report-only), 0 console errors and 0 page errors.
- Boot and login used a fresh, cookieless context. The only real password sign-in was bob's, typed at
  1 character per 400 ms. Log Out was exercised with a throwaway Guest session.
- Notifications: the QA copy has no notification source a non-root user can trigger (Task Manager's
  End Process and Reclaim are disabled, `svcctl` needs sys.admin, `su` is not available in the
  Terminal). UI-079, UI-080, UI-082 and the banner part of UI-151 were therefore checked in the shell's
  own dev harness (`wm/src/shell/dev-harness.tsx` on :5311, real shell code, fake kernel, **no CSP**).
  It posts through `handle.notify`, which uses the same `addNotifications` path as kernel messages.
- Evidence is under `docs/design/wave3/verify-a/` (below, `va/`). JSON files are the check logs
  (PASS/FAIL per assertion). Every screenshot cited here was read.

Legend: **VF** = VERIFIED-FIXED, **SB** = STILL-BROKEN, **NR** = NOT-REPRODUCIBLE.

## 2. Regressions and new findings

### Found and fixed

1. **The login-corner logo was soft at 1x** (logo audit, fix-boot-login area). `AtomLogo size={28}`
   is not a size the Bohr P is hinted for (DECISION.md §4: multiples of 16, 20 and 24). Centring it
   against the ~32.7 px text block also put it at y = 849.33. Fixes:
   - `ui/src/login/LoginScreen.tsx`: size 32, the master grid.
   - `ui/src/login/LoginScreen.module.css` `.brand`: `align-items: flex-end`, so the mark takes the
     row's whole-pixel bottom edge.
   - On :4718 it now sits at (24, 848, 32×32) at 1x and 2x in both themes
     (`logo-zoom-login-after.png` against `logo-zoom-menubar-login.png`).
   - The lock screen uses the same component, so it gets the same fix.
   - New test file `ui/src/login/verify-a-login-logo.test.tsx`, 2 tests. The size test fails with 28.
2. **UI-096 residual** (above).

### Checked, no regression

- **macOS look and feel, both themes:** traffic lights, unified toolbars, Control Centre,
  Notification Centre and Overview (`s1-*-dark.png`, `w-ui011-five-apps-dark.png`).
- **Reduced motion** (`rm-dark.json`):
  - window open and minimise have no transform or opacity frames;
  - there is no Dock magnification;
  - the snap preview appears with a 0 s transition;
  - Overview is laid out at once.
- **Keyboard:** Alt+C, Alt+N, Alt+W, Shift+F10, F3, Esc chains, the lock-screen Tab trap, and the
  Tab order without a BODY stop.
- **Dock:** WMD-10 click semantics hold. A click on the focused app's only window minimises it. This
  is the spec, not a bug.
- **CSP:** 0 violations on every run: boot, login, recovery, panic, unsupported, desktop, all
  overlays, Settings prefs, the 10-window perf run and Terminal typing.

### Seen, not changed (other owners, or cosmetic by design)

- **Unsupported-browser card:** 806 px tall. At 1280×800 it scrolls inside the page, and its footer
  line is below the fold. The Stitch reference card (790 px) would not fit either. Left as is;
  cosmetic.
- **Editor status bar:** says "saved v0 · synced" for a never-saved Untitled document
  (fix-files-editor; the gate already noted it).
- **Terminal:**
  - the content area has a 2 px accent focus outline (fix-terminal; noted by the gate, needs a
    design call);
  - it says "AI unavailable · plain shell" while the AI chip reads ready (UI-055, Workflow B);
  - `su` prints "switching users is not available in this Terminal yet", so the QA copy has no way
    for a user to raise notifications on demand (fix-terminal / Workflow B).
