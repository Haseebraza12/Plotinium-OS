# Plotinium design references

This folder holds the visual references for Plotinium's macOS-inspired (Liquid Glass era) interface: one folder per screen under [`stitch/`](./stitch/), designed with Google Stitch. The normative rules for colour, materials, type, icons, components and motion are in [specs/05-wm/visual-language-macos.md](../../specs/05-wm/visual-language-macos.md). Layout, content and exact strings for each screen are in [specs/05-wm/ui-design-system.md §3.8](../../specs/05-wm/ui-design-system.md). The code that implements them is `@plotinium/ui` (`ui/`). Its gallery previews every component in both themes:

```sh
pnpm --filter @plotinium/ui gallery         # dev server, http://localhost:4718
pnpm --filter @plotinium/ui gallery:build   # static build in ui/gallery/dist
```

## Logo and fonts (decided after these references were drawn)

The references below predate two decisions. Where they disagree, the decisions win:

- **Logo: the "Bohr P"** ([logo/DECISION.md](./logo/DECISION.md)). An electron shell around a dense nucleus, open at 1:30 where the one electron sits; the shell grows a stem on its left, so the atom is also the P of Plotinium. Four filled shapes on a 24-unit grid, no strokes, legible at 16 px. It replaced the two-orbit "luminous atom" that the boot, login and About references still draw. Normative text: [identity-and-branding.md §3.6](../../specs/00-product/identity-and-branding.md) and [visual-language-macos.md §3.6.2](../../specs/05-wm/visual-language-macos.md).
- **Fonts: Inter 4 and JetBrains Mono, both variable and self-hosted** ([fonts/DECISION.md](./fonts/DECISION.md), D15). Inter 4 with its optical-size axis for the UI; JetBrains Mono for the Terminal, the Editor, paths and pids. D15 first chose Geist Mono and switched on 2026-09-30, when its reversal trigger fired (UI-004: Geist Mono draws `r` like `ɪ` at 12–14 px on 1x screens). There is no font preload. Normative text: [visual-language-macos.md §3.5](../../specs/05-wm/visual-language-macos.md).

## Status: no Stitch export exists yet (checked 2026-09-25)

Every `generate_screen_from_text` call in the 2026-09-24 design run either timed out or returned only a session id. `list_screens` on project `12849137298552292712` was still `{}` when it was checked again on 2026-09-25. So **no screen folder contains a `screen.html` or `screenshot.png` from Stitch yet**. What each folder does contain:

| File             | What it is                                                                                                                                                                                               |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `notes.md`       | The exact prompt that was sent, the elements, their states, the intended animations and review notes. **Read this first.**                                                                               |
| `reference.html` | A hand-built render of the same prompt that uses the Plotinium Glass tokens. **It is not a Stitch export.** Most of these files also prototype the animations and the `prefers-reduced-motion` fallback. |
| `reference.png`  | A 1440 × 900 headless-Chrome capture of `reference.html`.                                                                                                                                                |
| `screen.json`    | The record of the Stitch request and its outcome (timeout or session id).                                                                                                                                |

When Stitch does return a screen, save it next to the reference as `screen.html` and `screenshot.png`, and put its screen id in `notes.md` (see "Editing screens in Stitch" below). If a Stitch export and a hand-built reference disagree, the spec decides. The tokens in `ui/src/tokens/tokens.css` were taken from these references (their CSS custom properties hold the exact colours, radii and blur values) and from the two Stitch design systems.

## Editing screens in Stitch

**Project:** `12849137298552292712` ("Plotinium OS"). **Design systems:** Plotinium Glass Dark `assets/10121591451242352758` and Plotinium Glass Light `assets/3690503530025860907`. **Model:** `GEMINI_3_8_FLASH`, device `DESKTOP`.

1. **Start from the notes.** Copy the "Final prompt" from the screen's `notes.md`. Change only what you mean to change, and keep the trademark rules of [visual-language-macos.md §3.2](../../specs/05-wm/visual-language-macos.md): no Apple logo, no Apple app names, no SF Symbols or SF Pro, and no copied wallpapers. Use our names: Files, Terminal, Editor, Task Manager, Settings, Search, Overview, Control Centre, Notifications.
2. **Generate.** In the Stitch web app, open the project and create the screen with the matching design system. Through the Stitch MCP tools, call `generate_screen_from_text` with `projectId`, `deviceType: "DESKTOP"`, `designSystem` and `modelId`. The call can take minutes and may time out on the client: **do not retry it**. Instead, poll `list_screens` until the screen appears.
3. **Refine.** Use `edit_screens` (or edit in the web app) for small changes and `generate_variants` to explore. Apply a design system to existing screens with `apply_design_system`. Keep each edit small, so the notes can record it.
4. **Export.** `get_screen` returns the screen's HTML and a screenshot. Save them as `stitch/<slug>/screen.html` and `stitch/<slug>/screenshot.png`, and update `screen.json` with the returned ids.
5. **Record.** In `notes.md`, fill in the screen id, the prompt you actually sent, and any change to elements, states or animations. If the export introduces a new colour, radius or blur, add it to `ui/src/tokens/tokens.css` (the only place values live), run `pnpm exec vitest run --config ui/vitest.config.ts` (the contrast and token tests), and update the spec if it is a new role.
6. **Review.** Compare the export with the component in the gallery, in both themes and with Reduce motion and Reduce transparency turned on. Components follow the spec, not the export: a difference is fixed in whichever of the two is wrong, with the reason recorded in `notes.md`.

To change a token-level decision (the accent, a material, a spring), edit `tokens.css` first, then regenerate the affected screens so that the references keep matching the code.
