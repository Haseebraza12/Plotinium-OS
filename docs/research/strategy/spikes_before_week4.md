## Evidence rules (apply to every spike)

1. **Pre-register first.** Criteria, weights (summing to 100), scales and pass thresholds for each decision are merged in a PR **before** any result is committed. The git timestamps prove the order.
2. **Where to run.** Use the Week-2 published lab-spec machine and Chrome **stable** (channel `chrome`), and log the version. Use a disk-backed profile (`launchPersistentContext`), never an incognito-style context, for anything that touches storage.
3. **How to sample.** Interleave the variants, discard warm-up, and take n ≥ 1,000 samples for latency percentiles (n ≥ 100 for heavy operations). Report p50, p95 and p99. Record the machine and its load. Where relevant, add a second run at a 4× CPU throttle.
4. **What to commit.** Raw JSON or CSV goes in `docs/evidence/<decision>/`, together with the harness (`pnpm bench:<x>`), a results table, and any plots or EXPLAIN plans.
5. **Include the loser.** Each record measures at least one option the team expects to lose, so that the comparison comes from the team's own numbers.
