- Backend D3 tx() SERIALIZABLE + Transport D4 op pipeline SERIALIZABLE + ORM D6 original vs Database D5 (READ COMMITTED + lock protocol) and ORM D6 amended :: Four different transaction helpers. Measured on PG 18.6: under SERIALIZABLE, 82-116% of writes retried on a freshly deployed (compact) database and 91-97% of cp -r attempts aborted with 10 concurrent writers. FOR UPDATE under SERIALIZABLE waits and then raises 40001, so it does not turn aborts into waits. READ COMMITTED without a rename lock corrupted the tree in 50/50 trials. => FIX: Use one server/vfs/tx.ts vfsTxn() for every mutation. Declare READ COMMITTED with an explicit lock protocol.
